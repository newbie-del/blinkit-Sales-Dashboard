 1. THE DATASET  -  IS IT REAL OR FAKE?
--------------------------------------------------------------------------------

  STATUS: **SYNTHETIC (generated), but built to faithfully match the real
          "BlinkIT Grocery Data" schema.**

  WHY IT IS SYNTHETIC:
    The public "BlinkIT Grocery Data.csv" could not be downloaded in the build
    environment. Every source URL tried returned HTTP 404:
      - github.com/AdityaGor/Blinkit-Sales-Analysis
      - github.com/rajatverma1/Blinkit-Analysis
      - github.com/Sagar-Chougule/Blinkit-Sales-Analysis
      - github.com/nikhilsthorat03/Blinkit-Data-Analysis
      - (and several others)
    None were reachable, so the dataset was RECONSTRUCTED by a Python script.

  WHAT "FAITHFUL RECONSTRUCTION" MEANS:
    It is NOT random noise. The generator reproduces the real dataset's:
      - exact 12-column schema + an added "Order Date" column
      - real identifier formats (FDX32, NCB42, DRC13, OUT027, etc.)
      - the real 16 item categories (Fruits and Vegetables, Snack Foods, ...)
      - the real 10 outlets with their true attributes (tier, size, type, year)
      - realistic value ranges and cardinalities
      - the SAME data-quality defects the real file is famous for (see section 3)
    Sales values are driven by an explicit DEMAND MODEL, so every insight is a
    genuine mathematical property of the data, not a number written to look good.

  THE DEMAND MODEL (how each sale value was produced):
      Sales = base_price(item_type)
            * outlet_type_multiplier      (Supermarket Type3 highest, Grocery lowest)
            * tier_multiplier             (Tier 3 > Tier 2 > Tier 1)
            * outlet_size_multiplier
            * maturity(years_since_establishment)
            * seasonality(month)          (Indian festive peak Oct-Nov)
            * weekend_uplift(weekday)
            * visibility_uplift(visibility)
            * yoy_growth(year)            (+18% 2022->2023 baked in)
            * lognormal_noise             (mean ~ 1.0)

  HONESTY NOTE:
    The README states this openly in a "Data provenance" callout. If you use
    the REAL Kaggle file instead, drop it into Dataset/ and skip the generator
    - the schema matches and the whole pipeline runs unchanged, EXCEPT the
    time-series queries (the real file has no Order Date column).

  SEED: 20240215 (fixed, so the dataset is identical on every regeneration)

 3. DATA-QUALITY DEFECTS DELIBERATELY INJECTED (to mirror the real file)
--------------------------------------------------------------------------------

  These were added ON PURPOSE so the cleaning stage is genuine, not theatrical:

    1. Item Fat Content  - 7 spellings for 2 real categories:
         "Low Fat", "low fat", "Low Fat ", "LF", "Regular", "reg", " Regular"
         (includes stray leading/trailing whitespace)
    2. Item Weight       - 17.2% missing (1,468 rows) - matches real file's rate
    3. Item Visibility   - 6.0% recorded as 0.00 (512 rows) - impossible for a
                           stocked product, a "not recorded" sentinel
    4. Duplicate rows    - 14 exact duplicates (simulated double-loaded ETL batch)
    5. Rating            - 1,263 rows carry more decimal precision than the
                           1-decimal collection scale; 1 value pushed above 5.0
    6. Outlet Size       - blank for 3 outlets (OUT010, OUT017, OUT045),
                           27.5% of rows
